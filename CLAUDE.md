# token.app

AI model pricing tracker and comparison tool built on Cloudflare Workers with Hono. Data sourced from OpenRouter API. Deployed at https://token.app (custom domain) and https://token-app.measurable.workers.dev.

## Stack
- **Runtime**: Cloudflare Workers
- **Framework**: Hono
- **Storage**: Cloudflare KV (`TOKEN_APP_KV`)
- **Data**: OpenRouter `/api/v1/models` (JSON) + `/rankings` (RSC payload scraping)
- **Secrets**: `REFRESH_SECRET` via `wrangler secret put`

## Key files
- `src/index.ts` — Hono routes (API + SSR page)
- `src/template.ts` — Full HTML/CSS/JS template (SSR, single-file SPA)
- `src/fetchers.ts` — OpenRouter data fetching, normalization, KV read/write
- `src/subscriptions.ts` — Static subscription plan data
- `src/types.ts` — All TypeScript interfaces
- `src/providers.ts` — Provider metadata (colors, display names)

## Dev
- `npx wrangler dev --port 8799` — local dev server
- `npm test` — `node:test` suite over the Epoch benchmark version join (`test/benchmarks.test.mjs`). No framework; bundles the TS module with esbuild and stubs `fetch`, so it touches no network. Run it before touching `src/benchmarks.ts`.
- `npm run deploy` — deploy to production. **Use this, not `npx wrangler deploy`**: the script is `node scripts/preflight-deploy.mjs && wrangler deploy`, so the check runs inline (not as a `predeploy` hook, which `ignore-scripts` would skip) and catches the undici breakage (archived; `docs/gotchas-archive.md`) before the upload starts rather than twenty lines into a stack trace. `npm run preflight` runs the check alone. Calling `wrangler deploy` directly still bypasses it — no package script can prevent that.
- Cron runs hourly (`0 * * * *`) to refresh model + rankings data
- Manual refresh: `POST /api/refresh` with `Authorization: Bearer <REFRESH_SECRET>`
- `wrangler.toml` is gitignored (contains KV namespace IDs)

## Gotchas

Settled ones live in `docs/gotchas-archive.md` (does not auto-load). This section is capped by the ~30KB CLAUDE.md budget — archive before adding.

- **Provider logos are SELF-HOSTED and `src/logos.ts` is GENERATED** (2026-08-17): every mark is served from `/logo/{slug}.svg` by our own Worker; nothing on the page calls `google.com/s2/favicons`, which used to see 41 requests per visit carrying the visitor's IP, our referrer and the list of providers they browsed. Edit `scripts/build-provider-logos.mjs` and run **`npm run logos`** — hand-edits to `src/logos.ts` are overwritten. The slug→icon map is **EXPLICIT-ONLY, same rule as `MODEL_MAP`**: the icon set holds near-misses (`ai2` is the Allen Institute, `ai21` is a different company; `ling` vs `kling`) that any substring match gets wrong, and a wrong logo is worse than none. Unmapped slugs render a generated initial tile, so the route answers for **every** provider — there is no null case, no broken image, and a new provider needs no deploy. Three further rules, each learned the hard way: **`currentColor` does not inherit into an SVG loaded through `<img>`** (it is its own document), so its parts are baked at generation time; **"mentions currentColor" is NOT "can be inverted"** — a mark that mixes it with fixed brand paint (AWS, Yi, LongCat) must never be flipped wholesale or `#F90` becomes blue, so only marks that are *entirely* the baked ink go in `MONO_LOGO_SLUGS` and get `filter: invert(1)` on dark (never on the treemap, where they sit on a white chip); and **check a mark at its real 13px, on BOTH backgrounds, before mapping it** — `xiaomimimo` is a two-line wordmark that rasterises to an illegible smear, and the inverted-brand-colour bug survived a contact sheet that was too small to show a colour shift. `npm run logos:check` (wired into the deploy preflight) fails if the committed file drifts from the generator, and the client appends `?v=LOGO_ASSET_VERSION` so the year-long `immutable` TTL cannot pin anyone to a stale mark. Scraping each vendor's own `/favicon.ico` was tried first and **rejected as unverifiable**: `anthropic.com/favicon.ico` served 167 bytes of HTML under an `image/*` content-type.
- **OpenRouter /rankings is JS-rendered now**: the SSR HTML no longer contains ranking data (turbopack Next.js app). `fetchRankingsFromOpenRouter()` uses the Cloudflare Browser Rendering binding via `@cloudflare/puppeteer`. Stable selector: `[data-testid="model-rankings-leaderboard-row"]` for models; Top Apps section has no testid (fallback to innerText regex). Requires `[browser]` binding in `wrangler.toml` and Workers Paid plan.
- **OpenRouter /rankings has NO period toggle**: the "This Week" / "Today" buttons in the new UI are model-search comboboxes, not period selectors. Models are fixed at 7-day rolling; apps are today-only. Don't try to click them to switch periods — won't work and silently produces duplicate data. To support UI 24H/7D/30D toggle, we accumulate hourly snapshots in D1 and aggregate over windows ourselves.
- **D1 rankings history**: append-only `rankings_snapshots` table (`migrations/0001_*.sql`). Cron writes ~30 rows/hour. Read paths: `readLatestModels(env, 'week')` for any UI period (models don't change with toggle); `readLatestApps(env)` for day, `aggregateApps(env, days)` for week/month. Aggregation takes LAST snapshot per identifier per day then SUMs across days.
- **Week/month aggregations are gated behind real history**: `getRankings(env, 'week'|'month')` calls `countAppDaysInRange()` first and returns `topApps[period]=[]` plus `appsHistoryDays/appsHistoryRequired` when fewer than N distinct calendar days of snapshots exist. Without this gate, a 1-day SUM gets labelled "7D" and looks identical to 24H — the "fake rankings" bug from 2026-05-28. Client (`emptyAppsMessage()` in `template.ts`) renders "X/Y days of history collected" so users see why the panel is empty. Real data lights up automatically as snapshots accumulate.
- **Template literal escaping**: Model descriptions can contain backticks and `${` — use `safeLiteral()` before embedding in template.ts.
- **`\'` is invalid in JS template literals**: backslash is silently ignored for single quotes. Use `this.hidden=true` instead of `this.style.display='none'` in inline handlers.
- **`/api/refresh` can't run the long category scrape**: HTTP `ctx.waitUntil()` is cancelled ~30s after the response (Cloudflare limit); only the *scheduled* (cron) handler has the 15-min budget for the ~2-3 min category scrape. `refreshAllData(env, { includeCategories })` gates it — cron passes `true`, `/api/refresh` awaits the fast path (models+rankings+market-share, ~45-60s, under the ~100s edge timeout) and leaves categories to the cron. Backgrounding a long job after a 202 silently truncates — don't.
- **Market-share legend: extract by CONTENT, not tag**: the `#market-share` rows are NOT reliably `<button>`-wrapped (OpenRouter changed the DOM; the spike's `<button>` assumption broke extraction → empty for 2 days). Walk up from each `a[href="/{author}"]` to the nearest ancestor whose text has a `%`, anchored on the link label. Reject non-author links (clean-slug regex + denylist) — the section holds a `/models?fmt=cards` CTA next to the unnamed "Others" aggregate. Sanitize on read too (`isAuthorSlug` in `readMarketShare`). Also: `page.waitForFunction(string)` THROWS under `@cloudflare/puppeteer` — poll with `page.evaluate(string)` instead.
- **"Top models by task" treemap = `task-spend` `spend` half, NOT `tokens`** (verified 2026-06-29): `/api/frontend/v1/rankings/task-spend` returns `{data:{spend,tokens}}`, each `{windowDays, macroCategories, tasks[]}`. OpenRouter's treemap tiles read "X% of all **spend**", so `taskSpendFromRaw` surfaces `data.spend` as top-level and carries the other half as `TaskSpend.tokens?` for the Spend/Tokens toggle. The two genuinely differ (classification 11.7% spend vs 9.76% tokens) and the tokens block reuses the SAME field names (`spendShare`/`spendShareOfTotal`) — only the values and per-task top models change, so a mix-up is silent. Tasks are tagged (`code:general_impl`) with NO label in the payload — OpenRouter curates the human labels, mirrored in the `TASK_LABELS` map (`openrouter-json.ts`, fallback `prettyTag()`). It's a 30-day SNAPSHOT (no time-series) → store in KV like apps, NOT D1. Category palette sampled from OpenRouter: general `#f76b15`, agent `#6e56cf`, code `#30a46c`, data `#0090ff`. `deltaPp == share` in the payload (new taxonomy, prior window ~0) — OpenRouter's own UI shows the same, so it's faithful, not a bug. Fetch is non-fatal in `refreshAllData` (catch→empty) so a task-spend outage can't block the primary models/apps/share refresh.

- **Benchmarks come from Epoch AI, NOT llm-stats or vendor cards** (2026-08-05): `epoch.ai/data/benchmarks.csv` is live, machine-readable, **CC BY** (attribution rendered under the chart — do not remove), and covers evals Epoch *runs itself* (`isSelfReported:false`). Why not the alternatives: llm-stats' live data is a **commercial** Data API with `/api/` robots-Disallowed, and their CC BY open mirror is DEAD (`AchilleasDrakou/LLMStats` last touched models/ **2025-02-02**, newest OpenAI = `o3`; the 359-star predecessor is explicitly DEPRECATED) — useful only as a schema blueprint. **Vendor model cards publish benchmarks as chart IMAGES** (Anthropic's Opus 5 post: "more than doubles Opus 4.8", no number; the docs model table has zero scores) so they are not machine-extractable. Third-party SEO aggregators contradict each other outright. Full write-up: `docs/proposals/2026-08-05-llm-stats-benchmark-integration-plan.md`.
- **`MODEL_MAP` in `benchmarks.ts` is EXPLICIT-ONLY — never add fuzzy matching**: Epoch lists "Muse Spark" (2026-04-08) while our catalogue carries `meta/muse-spark-1.1` — a **different model**. Fuzzy matching would staple one model's benchmarks onto another (worse than a miss). Unmapped Epoch names are returned in the payload (`unmapped[]`) so coverage extends in a data-only PR. GPQA Diamond has the broadest coverage, which is why it drives the headline Quality column. The file also records ~20 **deliberate rejections** with reasons (`Ministral 3B` → `ministral-3b-2512` is Ministral *3*; `Mistral Large 2` is `-2407` not `-2512` which is Large *3*) so a later data pass doesn't redo the analysis. **Don't record coverage counts here** — Epoch is live data and the numbers moved 314→317 scores / 65→68 unmapped in one overnight cron. `curl -s https://token.app/api/benchmarks | jq '{m:(.models|length), u:(.unmapped|length), a:(.ambiguous|length)}'` for the current figures.
- **Epoch's `Model` column is NOT a unique key — join on `id_model_version`** (2026-08-06, found by Codex): a display name can span several versions for two very different reasons, and only one is safe to merge. (a) *Effort/context variants* (`gpt-5.4-…_{low,high,xhigh}`, `claude-opus-4-6_32K`) — merged on purpose, keeping the best score and recording `variant`. (b) *Different models sharing a name* (`mistral-large-2407` vs `-2411`, four months apart; `gemini-3.1-pro-preview` vs `-customtools`, separate entries in our own catalogue). Merging (b) welds one snapshot's GPQA to another's SWE-bench — **a model that never existed**, same class as the fake-7D bug. GPT-4o, GPT-3.5 Turbo, Gemini 2.5 Flash and DeepSeek-V3.2 were all chimeras before this landed. `versionBase()` strips the (a) suffixes so only (b) survives; `VERSION_PIN` then names the one version to accept, explicit like `MODEL_MAP`. The gating asymmetry is deliberate: a **pinned** name is gated on its pin *always* — gating only on a live collision leaves a hole, because if Epoch drops the older snapshot the name stops colliding and the wrong rows sail in — while an **unpinned** name is gated only when it actually collides, that collision being the signal a pin is now needed. Three outcomes, and a pin **rescues** a name rather than dropping it: pin present → that version is accepted and rows from any other base are skipped, so the model scores; pin **missing** from the export → the name goes to `ambiguous[]` and is dropped, never re-pointed; unpinned collision → also `ambiguous[]`, dropped. Nothing is ever merged across bases. `id_model_version` is **required** (absence throws; the fetch is non-fatal so KV keeps its last good copy) and a blank value never scores. **Bounded limitation, made visible rather than prevented**: `versionBase()` infers "effort variant" from a suffix, so a future Epoch id genuinely ending in `_max`/`_high`/`_NNK` collapses into its stem — Epoch publishes nothing that would let the join decide. So `versions[]` records **every** raw id that contributed, winners *and* losers; recording only winners hides exactly the evidence you need. `npm test` pins the whole truth table. **When a name matches, check the DATES before mapping** — this has caught three bad mappings, and the release date is the discriminator every time: compare Epoch's `Version release date` against the catalogue's `createdAt`. Same date = same model; a gap of months = a different release, so don't map. `Gemini 3.1 Flash-Lite` (Epoch 03-03) is the **preview**, not GA (05-07); mapping it to GA attributed preview scores to a release Epoch never benchmarked. `Grok 4.3 Beta` (04-17 vs our 04-30) stays unmapped. `Gemini 3.5 Flash-Lite` passes: 07-21 both sides, no preview entry exists.
- **Model usage history joins on catalogue `id`, and is gated on board MEMBERSHIP, not age** (2026-08-12): D1 holds only OpenRouter's top-15, so few catalogue models have any history (**31 of 406** when measured 2026-08-12 — a live number that drifts, same rule as the Epoch counts above; re-measure with `npx wrangler d1 execute token-app-rankings --remote --command "SELECT COUNT(DISTINCT identifier) FROM rankings_snapshots WHERE kind='model' AND period='week'"`). Of those, **5 are keyed under a permaslug the catalogue never uses** — these are historical rows, so the list is stable: `anthropic/claude-4.7-opus` against our `anthropic/claude-opus-4.7`, likewise `-4.6-sonnet` and `-4.8-opus`, plus `poolside/laguna-m.1` and `openrouter/owl-alpha`. Never bridge those by similarity — it staples one model's usage onto another (the `MODEL_MAP` lesson). The freshness gate is membership in the **latest snapshot**, not an age window: the board is scraped hourly, so a model that charted at 09:00 and dropped by 10:00 still has a row dated *today*, and any day-granularity check hands it a rank it no longer holds. Everything anchors on the board's own newest snapshot, **never wall-clock** — `readSeries` computes its cutoff from `Date.now()` unless passed an upper anchor, which silently blanks **every** panel once the cron has been down longer than the window. The board query and `readSeries` must agree on scope (`kind`/`period`/`category IS NULL`) or the anchor comes from one row while the history excludes it. `npm test` pins all of this.
- **A test stub that ignores its query can only confirm what you already believe** (2026-08-12): the first D1 stub returned a fixed series whatever SQL it got, so the `Date.now()` cutoff bug above passed a test written to catch exactly it. Stubs must **derive** behaviour from the SQL text, never hardcode the intended answer — the second attempt at this fix reproduced the very bug it was fixing, and only mutation testing caught it. Watch for **equivalent mutants** too: dropping `category IS NULL` was undetectable until the fixture carried a row that clause alone excludes, placed *before* the anchor (rows after it are already excluded by the upper bound, so they test a different clause).

- **Editing `src/subscriptions.ts` does NOT change the live site until a refresh runs** (2026-08-17): `getSubscriptions` reads **KV** (`subscriptions:all`) and falls back to the static array *only when the key is absent*; prod KV is seeded, so a deploy alone changes nothing. `refreshAllData` unconditionally rewrites the key from the compiled-in array (`fetchers.ts`, "static data, updated on deploy"), so the order is **deploy → propagate → refresh → verify**, and the verification probe must read `/api/subscriptions`, not just the page. Locally the same trap bites harder: `wrangler dev`'s miniflare KV persists in `.wrangler/state/v3/kv/.../*.sqlite` and will happily serve a **months-old** blob (it served 16 subscriptions naming GPT-4o against a 28-entry file). `DELETE FROM _mf_entries WHERE key='subscriptions:all'` forces the re-seed — the column is `blob_id`, not `value`.
- **Never claim a "#1"/"top score" without significance-gating it** (2026-08-05, gate rebuilt 2026-08-13): GPQA Diamond is SATURATED — its top models sit inside one stderr, so sorting it hands #1 to a coin flip (it once picked a March model over the July frontier). `leadingBenchmark()` (`template.ts`) takes the best-separated benchmark and returns null below `BENCH_LEAD_SIGMA`, so the card is omitted rather than fabricated. Three rules the gate depends on, each of which was wrong once: σ divides by the **combined** error of the two scores (`sqrt(e1²+e2²)`), not the leader's alone — dividing by one measurement overstates separation by up to √2; **both** models must publish a stderr, since quadrature treats a missing one as perfect certainty and would let a runner-up's error bar carry someone else's claim; and the threshold is **2σ, not 1**, because the strip picks the largest gap across six benchmarks — selecting the winner for looking good — so the nominal figure understates the false-positive rate. Don't record σ values here; they drift with Epoch. Same class as the fake-7D bug. **GPQA still stays the default Quality column** — only the top cluster is tied, it discriminates across the catalogue, and it covers far more models than SWE-bench.
- **Per-host endpoints are fetched LAZILY, per model page** (`src/endpoints.ts`, 2026-08-05): 338 calls per cron is unaffordable and you can't know which models have many hosts without asking. Read-through KV (6h TTL), 4s timeout, failures return null → panel omitted, never a blocked render; **empty results are deliberately NOT cached** or one blip persists as "no hosts" for 6h. Labels come from `tag` (service tier / region), **never a counter** — numbering duplicates "#1 #2" discards the only interesting part. Headline counts providers separately from options: GPT-5.6 Sol's 4× spread is entirely across OpenAI's own flex/standard/priority tiers, and calling that "6 hosts" implies competition that isn't there. **`latency_last_30m`/`throughput_last_30m` are null on every endpoint of every model probed — do not build a speed feature on them.**
- **Don't `/api/refresh` straight after `wrangler deploy`** (hit twice, 2026-08-05): the refresh can execute on the **pre-deploy** Worker — it wrote old-normalization models to KV, and new routes 404'd at some PoPs. Wait for propagation, then refresh, then verify. **`wrangler deployments status` showing `(100%)` does NOT mean propagated** — that is the version's traffic allocation and it prints 100% straight away. Gate on a **probe of something only the new code serves** (a new route, or a changed string in the SSR HTML), and treat even that as evidence rather than proof, since one client only reaches one PoP.

Two deviations from the stock gstack routing block, both deliberate:

1. **Shipping does NOT route to `/ship` or `/land-and-deploy`.** This repo has a standing workflow the user set explicitly: **branch → commit → push → PR → `/codex` review → merge → `wrangler deploy` → refresh → verify live**. Follow that. Don't fire `/api/refresh` straight after a deploy (see gotchas). `wrangler deployments status` reading `(100%)` is **not** a propagation check — that is the version's traffic allocation and it prints 100% immediately. The real gate is to **probe a signal only the new code emits** (a new route, or a changed string in the SSR HTML) and see it answer correctly before refreshing. Even that is evidence, not proof: one client reaches one PoP.
2. **"When in doubt, invoke the skill" does not apply here.** The global config in `~/.claude/CLAUDE.md` treats subagents and broad skill runs as expensive and asks for direct `Grep`/`Glob`/`Read` when those suffice. Route to a skill when the request *clearly* matches; otherwise just do the work. `/autoplan` is omitted for the same reason — it chains four full reviews.
