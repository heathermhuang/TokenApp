# token.app

AI model pricing tracker and comparison tool built on Cloudflare Workers with Hono. Data sourced from OpenRouter API. Deployed at https://token.app (custom domain) and https://token-app.measurable.workers.dev.

## Stack
- **Runtime**: Cloudflare Workers
- **Framework**: Hono
- **Storage**: Cloudflare KV (`TOKEN_APP_KV`)
- **Data**: OpenRouter `/api/v1/models` (JSON) + `/rankings` (RSC payload scraping)
- **Secrets**: `REFRESH_SECRET` via `wrangler secret put`

## Key files
- `src/index.ts` — Hono routes (API + SSR page)
- `src/template.ts` — Full HTML/CSS/JS template (SSR, single-file SPA)
- `src/fetchers.ts` — OpenRouter data fetching, normalization, KV read/write
- `src/subscriptions.ts` — Static subscription plan data
- `src/types.ts` — All TypeScript interfaces
- `src/providers.ts` — Provider metadata (colors, display names)

## Dev
- `npx wrangler dev --port 8799` — local dev server
- `npm test` — `node:test` suite over the Epoch benchmark version join (`test/benchmarks.test.mjs`). No framework; bundles the TS module with esbuild and stubs `fetch`, so it touches no network. Run it before touching `src/benchmarks.ts`.
- `npx wrangler deploy` — deploy to production
- Cron runs hourly (`0 * * * *`) to refresh model + rankings data
- Manual refresh: `POST /api/refresh` with `Authorization: Bearer <REFRESH_SECRET>`
- `wrangler.toml` is gitignored (contains KV namespace IDs)

## Gotchas
- **OpenRouter /rankings is JS-rendered now**: the SSR HTML no longer contains ranking data (turbopack Next.js app). `fetchRankingsFromOpenRouter()` uses the Cloudflare Browser Rendering binding via `@cloudflare/puppeteer`. Stable selector: `[data-testid="model-rankings-leaderboard-row"]` for models; Top Apps section has no testid (fallback to innerText regex). Requires `[browser]` binding in `wrangler.toml` and Workers Paid plan.
- **OpenRouter /rankings has NO period toggle**: the "This Week" / "Today" buttons in the new UI are model-search comboboxes, not period selectors. Models are fixed at 7-day rolling; apps are today-only. Don't try to click them to switch periods — won't work and silently produces duplicate data. To support UI 24H/7D/30D toggle, we accumulate hourly snapshots in D1 and aggregate over windows ourselves.
- **D1 rankings history**: append-only `rankings_snapshots` table (`migrations/0001_*.sql`). Cron writes ~30 rows/hour. Read paths: `readLatestModels(env, 'week')` for any UI period (models don't change with toggle); `readLatestApps(env)` for day, `aggregateApps(env, days)` for week/month. Aggregation takes LAST snapshot per identifier per day then SUMs across days.
- **Week/month aggregations are gated behind real history**: `getRankings(env, 'week'|'month')` calls `countAppDaysInRange()` first and returns `topApps[period]=[]` plus `appsHistoryDays/appsHistoryRequired` when fewer than N distinct calendar days of snapshots exist. Without this gate, a 1-day SUM gets labelled "7D" and looks identical to 24H — the "fake rankings" bug from 2026-05-28. Client (`emptyAppsMessage()` in `template.ts`) renders "X/Y days of history collected" so users see why the panel is empty. Real data lights up automatically as snapshots accumulate.
- **Empty-overwrite guard**: `refreshAllData` refuses to record a snapshot when scraping yields 0 models AND 0 apps. Stops silent cache poisoning if OpenRouter's UI changes again — keeps last-good D1 data and surfaces `rankingsError` instead.
- **`[]` is truthy in JS**: `appsData.week || appsData.day` returns the empty `.week` array, not `.day`. The rankings UI fallback checks `byPeriod.length > 0` instead. Worth remembering for any future period-keyed shape.
- **Template literal escaping**: Model descriptions can contain backticks and `${` — use `safeLiteral()` before embedding in template.ts.
- **`\'` is invalid in JS template literals**: backslash is silently ignored for single quotes. Use `this.hidden=true` instead of `this.style.display='none'` in inline handlers.
- **`/api/refresh` can't run the long category scrape**: HTTP `ctx.waitUntil()` is cancelled ~30s after the response (Cloudflare limit); only the *scheduled* (cron) handler has the 15-min budget for the ~2-3 min category scrape. `refreshAllData(env, { includeCategories })` gates it — cron passes `true`, `/api/refresh` awaits the fast path (models+rankings+market-share, ~45-60s, under the ~100s edge timeout) and leaves categories to the cron. Backgrounding a long job after a 202 silently truncates — don't.
- **Market-share legend: extract by CONTENT, not tag**: the `#market-share` rows are NOT reliably `<button>`-wrapped (OpenRouter changed the DOM; the spike's `<button>` assumption broke extraction → empty for 2 days). Walk up from each `a[href="/{author}"]` to the nearest ancestor whose text has a `%`, anchored on the link label. Reject non-author links (clean-slug regex + denylist) — the section holds a `/models?fmt=cards` CTA next to the unnamed "Others" aggregate. Sanitize on read too (`isAuthorSlug` in `readMarketShare`). Also: `page.waitForFunction(string)` THROWS under `@cloudflare/puppeteer` — poll with `page.evaluate(string)` instead.
- **Model token-usage chart source = `model-rankings-chart`, NOT `/models`** (verified 2026-06-28): the year-long per-MODEL chart is built from `model-rankings-chart` (52 weekly points; each week = its top-9 + an "Others" bucket). `/rankings/models?view=week` is the LEADERBOARD feed and only carries the last ~6 days — it CANNOT drive a year chart. "Others" is genuinely ~40%/week and that MATCHES OpenRouter (confirmed against their own hover tooltip: Others is the big PINK base band, ~47%). `modelShareSeries` displays the UNION of every week's top-9 (canonicalized keys, for cross-week continuity) and keeps "Others" as `entities[0]` → the BOTTOM band. The old bug projected TODAY's top-9 backward → historical weeks rendered empty/grey (was mislabelled a "D1 depth" caveat).
- **"Top models by task" treemap = `task-spend` `spend` half, NOT `tokens`** (verified 2026-06-29): `/api/frontend/v1/rankings/task-spend` returns `{data:{spend,tokens}}`, each `{windowDays, macroCategories, tasks[]}`. OpenRouter's treemap tiles read "X% of all **spend**", so `taskSpendFromRaw` surfaces `data.spend` (classification 11.7% spend ≠ 9.76% tokens — they differ). Tasks are tagged (`code:general_impl`) with NO label in the payload — OpenRouter curates the human labels, mirrored in the `TASK_LABELS` map (`openrouter-json.ts`, fallback `prettyTag()`). It's a 30-day SNAPSHOT (no time-series) → store in KV like apps, NOT D1. Category palette sampled from OpenRouter: general `#f76b15`, agent `#6e56cf`, code `#30a46c`, data `#0090ff`. `deltaPp == share` in the payload (new taxonomy, prior window ~0) — OpenRouter's own UI shows the same, so it's faithful, not a bug. Fetch is non-fatal in `refreshAllData` (catch→empty) so a task-spend outage can't block the primary models/apps/share refresh. **UPDATE 2026-06-29: the treemap now exposes BOTH halves via a Spend/Tokens toggle** — `taskSpendFromRaw` returns top-level=spend + `TaskSpend.tokens?`; tokens block reuses the SAME field names (`spendShare`/`spendShareOfTotal`), only values + per-task top-models differ (spend top=claude-4.7-opus, tokens top=hy3-preview).
- **`/api/*` edge cache lags the cron by HOURS** (2026-06-29): Cloudflare serves `/api/task-spend` & `/api/market-share` with `max-age` up to 14400 (zone override; routes set 3600) + `cf-cache-status: HIT`, so after the hourly cron updates KV the page keeps a stale snapshot — this kept the new Spend/Tokens toggle HIDDEN for hours (visibility flips on `data.tokens` presence). Fix: client appends a 10-min time-bucket key (`fetch('/api/task-spend?b=' + Math.floor(Date.now()/600000))`) — edge still caches within each window but data refreshes ~10min. A cache-BUSTED URL (`?_=ts`) proves KV is fresh while the plain URL serves stale. **Leaderboard + apps board are SSR-embedded (no client `/api/rankings` fetch on load).** **UPDATE 2026-06-30 (caching policy pass):** measured live — the SSR page `/` is NOT edge-cached (no `cf-cache-status`; re-rendered per request from KV/D1), so the boards are already fresh to ≤1 cron cycle (the earlier "governed by page HTML cache → lags hours" worry does NOT hold). The bust is now consolidated in `withBust(url)` (`template.ts`, **top-level** script scope so both `init()` and the DOMContentLoaded handler reach it; appends a 10-min bucket, `?b=` or `&b=` as needed) and applied to the 3 **live** fetches: `/api/rankings` (period/category toggle — the previously-missed one, busted via `withBust(buildRankingsUrl(p))` + the SSR-fallback fetch), `/api/market-share`, `/api/task-spend`. **Slow** endpoints (`/api/models`, `/api/subscriptions`, `/api/rankings/categories`) stay un-busted (4h edge cache fine — change rarely). Same policy block sits atop the API routes in `index.ts`. Spec: `docs/superpowers/specs/2026-06-30-caching-freshness-policy-design.md`.

- **Benchmarks come from Epoch AI, NOT llm-stats or vendor cards** (2026-08-05): `epoch.ai/data/benchmarks.csv` is live, machine-readable, **CC BY** (attribution rendered under the chart — do not remove), and covers evals Epoch *runs itself* (`isSelfReported:false`). Why not the alternatives: llm-stats' live data is a **commercial** Data API with `/api/` robots-Disallowed, and their CC BY open mirror is DEAD (`AchilleasDrakou/LLMStats` last touched models/ **2025-02-02**, newest OpenAI = `o3`; the 359-star predecessor is explicitly DEPRECATED) — useful only as a schema blueprint. **Vendor model cards publish benchmarks as chart IMAGES** (Anthropic's Opus 5 post: "more than doubles Opus 4.8", no number; the docs model table has zero scores) so they are not machine-extractable. Third-party SEO aggregators contradict each other outright. Full write-up: `docs/proposals/2026-08-05-llm-stats-benchmark-integration-plan.md`.
- **Epoch's CSV needs a real RFC-4180 parser**: it embeds newlines AND commas inside quoted fields ("Training compute notes" runs to paragraphs) — a naive `split('\n')` yields **6541 fragments for 1107 records**. `parseCsv()` in `benchmarks.ts` is hand-rolled for this. Parse cost ~55ms CPU for 2.5MB — fine against the Worker budget.
- **`MODEL_MAP` in `benchmarks.ts` is EXPLICIT-ONLY — never add fuzzy matching**: Epoch lists "Muse Spark" (2026-04-08) while our catalogue carries `meta/muse-spark-1.1` — a **different model**. Fuzzy matching would staple one model's benchmarks onto another (worse than a miss). Unmapped Epoch names are returned in the payload (`unmapped[]`) so coverage extends in a data-only PR. GPQA Diamond has the broadest coverage, which is why it drives the headline Quality column. The file also records ~20 **deliberate rejections** with reasons (`Ministral 3B` → `ministral-3b-2512` is Ministral *3*; `Mistral Large 2` is `-2407` not `-2512` which is Large *3*) so a later data pass doesn't redo the analysis. **Don't record coverage counts here** — Epoch is live data and the numbers moved 314→317 scores / 65→68 unmapped in one overnight cron. `curl -s https://token.app/api/benchmarks | jq '{m:(.models|length), u:(.unmapped|length), a:(.ambiguous|length)}'` for the current figures.
- **Epoch's `Model` column is NOT a unique key — join on `id_model_version`** (2026-08-06, found by Codex): when found, **33 of 91 mapped names spanned >1 version** — a measurement that motivated the rule, not a figure to rely on. Two very different reasons, and only one is safe to merge. (a) *Effort/context variants* — `gpt-5.4-…_{low,high,xhigh}`, `claude-opus-4-6_32K` — merged on purpose, keeping the best score and recording `variant`. (b) *Different models sharing a display name* — `mistral-large-2407` vs `-2411` (four months apart), `gemini-3.1-pro-preview` vs `-customtools` (a separate model in our own catalogue). Merging (b) makes `best` weld one snapshot's GPQA to another's SWE-bench: **a model that never existed**, same class as the fake-7D bug. `versionBase()` strips the (a) suffixes so only (b) survives; `VERSION_PIN` then names the one version to accept, explicit like `MODEL_MAP`. Two gating rules, and the asymmetry is deliberate: a **pinned** name is gated on its pin *always* (gating only on a live collision leaves a hole — if Epoch drops the older snapshot the name stops colliding and the wrong rows sail in; if the pinned version disappears the name is dropped, never re-pointed), while an **unpinned** name is gated only when it actually collides, since that collision is the signal a pin is now needed. Either way the result lands in `ambiguous[]` and is **dropped, never merged**. `id_model_version` is a **required** column (absence throws; the fetch is non-fatal so KV keeps its last good copy) and a blank or whitespace-only value never scores. **Known bounded limitation**: `versionBase()` infers "effort variant" from a suffix, so a future Epoch id genuinely ending in `_max`/`_high`/`_NNK` would collapse into its stem — Epoch publishes no metadata that would let the join decide. It is therefore made *visible* rather than prevented: `versions[]` on each model records **every** raw id that contributed, winners and losers. Recording only winners hides exactly the evidence you need. `npm test` pins this whole truth table. GPT-4o, GPT-3.5 Turbo, Gemini 2.5 Flash and DeepSeek-V3.2 were already chimeras before this landed. **When a name matches, check the DATES before mapping** — this has caught three bad mappings now, and the release date is the discriminator every time: compare Epoch's `Version release date` against the catalogue entry's `createdAt`. Same date = same model; a gap of months = a different release, so don't map. `Gemini 3.1 Flash-Lite` (Epoch 03-03) is the **preview** (created 03-03), not GA (05-07) — mapping it to GA attributed preview scores to a release Epoch never benchmarked. `Grok 4.3 Beta` (04-17 vs our 04-30) stays unmapped because neither feed says the weights match. `Gemini 3.5 Flash-Lite` passes: 07-21 both sides, no preview entry exists.
- **A page that exists is not a page you can reach** (2026-08-06): 339 `/model/{slug}` pages shipped in the sitemap — crawlers found all of them, humans could reach **4** (the superlative cards). Every table row's model name linked *off-site* (`getModelUrl()` → Hugging Face / OpenAI docs / OpenRouter), so the pages had no front door for a week. The name now links to `/model/{slug}` and the vendor link is a hover-revealed icon (`@media (hover: none)` keeps it visible on touch). When you ship programmatic pages, wire the internal entry point in the same PR as the sitemap.
- **`safeUrl()` is not HTML escaping**: it only checks the `https://` prefix, so a poisoned `huggingFaceId` carrying a double-quote plus a tag passes it and breaks out of the `href`. Every caller must **also** `escape()` at the attribute boundary. (`getProviderUrl` is safe — it reads a static map.)
- **The Pareto chart must sit ABOVE the models table**: measured — below it, `#pareto-section` lands at offsetTop ~28,000px behind 338 rows. Also: `.market-share` carries **no layout** (the rankings tab supplies its own container), so the panel uses `.table-wrap` + `.leaderboard` instead. Free models are excluded from the plot deliberately (log(0) has no axis home); several provider brand colours are near-white so every dot needs a stroke to survive the light theme.

- **`isOpenSource` = `Boolean(raw.hugging_face_id)`, never a name/provider heuristic** (fixed 2026-08-05): the old list treated whole authors as open (`'google'`, `'qwen'`), so every proprietary Gemini and Qwen-Max read as open-weight while GLM-5.2, Kimi K3 and gpt-oss-120b (public weights) read as proprietary. **125 models reclassified**, 125→152 open. Wrong for every user of the homepage "Open Source" filter until then. Caught only because the superlative strip surfaced "best open weights → Gemini 3.6 Flash".
- **Never claim a "#1"/"top score" without significance-gating it** (2026-08-05): GPQA Diamond is SATURATED — the top 10 models sit within one stderr (a 0.5pp lead with ±1.6pp bars), so sorting it hands #1 to a coin flip (it picked a March model over the July frontier). Measured σ-gaps: SimpleQA 2.03σ and SWE-bench 1.71σ discriminate; GPQA 0.29σ, FrontierMath T1–3 0.76σ, T4 0.94σ, OTIS AIME 0.00σ do not. `leadingBenchmark()` (`template.ts`) picks the best-separated benchmark and returns null below 1σ → card omitted, never fabricated; a missing stderr scores 0σ so unproven gaps read as ties. Frontier chart shows a tie warning on saturated benchmarks. Same class as the fake-7D bug. **GPQA still stays the default Quality column** — only the top cluster is tied, it discriminates 94%→29% across the catalogue, and it covers 70 models vs SWE-bench's 27.
- **Per-host endpoints are fetched LAZILY, per model page** (`src/endpoints.ts`, 2026-08-05): 338 calls per cron is unaffordable and you can't know which models have many hosts without asking. Read-through KV (6h TTL), 4s timeout, failures return null → panel omitted, never a blocked render; **empty results are deliberately NOT cached** or one blip persists as "no hosts" for 6h. Labels come from `tag` (service tier / region), **never a counter** — numbering duplicates "#1 #2" discards the only interesting part. Headline counts providers separately from options: GPT-5.6 Sol's 4× spread is entirely across OpenAI's own flex/standard/priority tiers, and calling that "6 hosts" implies competition that isn't there. **`latency_last_30m`/`throughput_last_30m` are null on every endpoint of every model probed — do not build a speed feature on them.**
- **Don't `/api/refresh` straight after `wrangler deploy`** (hit twice, 2026-08-05): the refresh can execute on the **pre-deploy** Worker — it wrote old-normalization models to KV, and new routes 404'd at some PoPs. Wait for propagation, then refresh, then verify. **`wrangler deployments status` showing `(100%)` does NOT mean propagated** — that is the version's traffic allocation and it prints 100% straight away. Gate on a **probe of something only the new code serves** (a new route, or a changed string in the SSR HTML), and treat even that as evidence rather than proof, since one client only reaches one PoP.

Two deviations from the stock gstack routing block, both deliberate:

1. **Shipping does NOT route to `/ship` or `/land-and-deploy`.** This repo has a standing workflow the user set explicitly: **branch → commit → push → PR → `/codex` review → merge → `wrangler deploy` → refresh → verify live**. Follow that. Don't fire `/api/refresh` straight after a deploy (see gotchas). `wrangler deployments status` reading `(100%)` is **not** a propagation check — that is the version's traffic allocation and it prints 100% immediately. The real gate is to **probe a signal only the new code emits** (a new route, or a changed string in the SSR HTML) and see it answer correctly before refreshing. Even that is evidence, not proof: one client reaches one PoP.
2. **"When in doubt, invoke the skill" does not apply here.** The global config in `~/.claude/CLAUDE.md` treats subagents and broad skill runs as expensive and asks for direct `Grep`/`Glob`/`Read` when those suffice. Route to a skill when the request *clearly* matches; otherwise just do the work. `/autoplan` is omitted for the same reason — it chains four full reviews.
